## 실측 조사 결과 (설계 근거)

Community Dragon 실데이터를 조사해 필터 규칙의 근거를 확보했다. **추측이 아닌 관측값이다.**

### 챔피언

| 관측 | 값 |
|---|---|
| Set 17 챔피언 총계 | **83** |
| `TFT17_` 접두사 보유 | **73** |
| **비어 있지 않은 `traits` 보유** | **63** |
| 특성 이름 형식 | 이미 한글 |
| 정사각 아이콘 필드 | `tileIcon` (`squareIcon` 은 스플래시) |

10개 차이(73 → 63)는 PVE 몬스터 · 소환수로 추정된다. 실제 TFT 한 세트의 플레이어블 챔피언은 60개 내외이므로 **63이 타당한 수치**다.

### 아이템

전체 3,680개가 전 세트에 걸쳐 혼재한다. 조사 결과:

| 분류 | 개수 | 판별 근거 |
|---|---|---|
| **기본 재료** | **정확히 10** | 다른 아이템의 `composition` 배열에 등장 + 이름이 번역됨 |
| 조합 아이템 (번역됨, 전 세트) | 295 | `composition` 이 비어 있지 않음 |
| ├ `TFT_Item_` 계열 (클래식 상시) | 49 | |
| └ `TFT17_` 계열 (현재 세트 전용) | 16 | |
| 미번역 / 폐기 | 14 | 이름이 `tft_item_name_` 로 시작하거나 `null` |
| 내부 보상 트리거 | 110 | `GrantOrbs*`, `GrantCompletedAnvil` 등 — **아이템이 아님** |

도출된 기본 재료 10개: 사슬 조끼 · 굽은 활 · 여신의 눈물 · 음전자 망토 · 쇠약의 장갑 · 스파툴라 · B.F. 대검 · 거인의 허리띠 · 쓸데없이 큰 지팡이 · 프라이팬 — **정확히 TFT 표준 10종과 일치한다.**

> **핵심**: 기존 코드의 `"_Item_" in id` 문자열 검사는 `GrantOrbs` 같은 내부 트리거까지 포함시킨다.
> `composition` 관계를 이용한 **데이터 기반 판별**이 정확하다.

### FQ1. 아이템 목록의 범위는? (Business Rules)

A) **클래식 + 현재 세트** — `TFT_Item_` 계열 49개 + `TFT17_` 계열 16개 + 기본 재료 10개 = **약 75개**.
   현재 게임에서 실제로 만들 수 있는 아이템에 가장 근접 ← **추천**

   누락은 없지만 구세트 아이템이 대부분이라 노이즈가 크다

C) **클래식만** — `TFT_Item_` 계열 49개 + 기본 재료 10개 = **약 59개**.
   가장 안정적이지만 현재 세트 전용 아이템 16개가 빠진다

### FQ2. 챔피언 선별 규칙은? (Business Rules)

Set 17 챔피언 83개 중 무엇을 노출할지 결정합니다.

A) **`traits` 가 비어 있지 않은 것만** → 약 63개.
   특성이 없는 유닛은 PVE 몬스터 · 소환수이므로 자연스럽게 걸러진다. 데이터 기반이라 세트가 바뀌어도 유효 ← **추천**

   가장 엄격하지만 접두사 규칙이 깨지는 챔피언(예: 이벤트 유닛)을 놓칠 수 있다

### FQ3. 디스크 캐시를 언제 갱신할까요? (Data Flow)

CDragon 데이터는 게임 패치마다 갱신됩니다. 캐시가 영구적이면 새 패치 내용이 반영되지 않습니다.

A) **TTL 방식** — 캐시 파일이 N시간(예: 24시간)보다 오래되면 재페치. 자동 갱신되고 구현이 단순 ← **추천**

B) **수동 삭제만** — 캐시가 있으면 무조건 사용. 갱신하려면 `data/cache/` 를 직접 지운다. 가장 단순하고 예측 가능하지만 방치되기 쉽다

C) **버전 키 방식** — CDragon 패치 버전을 캐시 파일명에 포함해 버전이 바뀌면 자동으로 새 파일 사용. 정확하지만 버전 조회를 위한 추가 요청이 필요

### FQ4. `TFT_SET` 미설정 시 동작은? (Error Handling)

DQ5-B 로 세트 번호를 환경변수로 분리하기로 했습니다. 값이 없을 때의 기본 동작입니다.

A) **하드코딩 기본값 `17`** — 환경변수가 없으면 17 사용. 예측 가능하고, 세트 전환 시 코드 한 줄만 수정 ← **추천**

B) **CDragon 의 최신 세트 자동 감지** — `sets` 키 중 최대 숫자. 새 세트 출시 시 자동 대응하지만, 출시 직후 데이터가 불완전한 기간에 화면이 비어 보일 수 있다

C) **미설정 시 오류** — 명시적 설정을 강제. 안전하지만 `.env` 없이는 서버가 뜨지 않아 개발 편의가 떨어진다

### FQ5. 특성(Trait) 데이터를 백엔드에서 어떻게 다룰까요? (Domain Model)

UQ1-C 로 **프론트에는 특성 이름 문자열만** 전달하기로 확정했습니다. 백엔드 내부 처리 방식입니다.

A) **`traits()` 메서드를 만들지 않는다** — 챔피언의 `traits[]` 가 이미 한글 이름이므로 그대로 전달. 코드가 가장 단순하고 UQ1-C 와 정확히 일치 ← **추천**

B) **내부 전용 `traits()` 를 만들되 노출하지 않는다** — 이름 정규화나 검증에 사용. 향후 특성 아이콘이 필요해지면 확장 지점이 된다

C) **`/api/traits` 엔드포인트까지 만든다** — UQ1-C 결정을 넘어서는 선제 구현
