# Performance Test Instructions

## 적용 범위

**부하 테스트는 수행하지 않는다.** 근거:

- 완료 기준이 **로컬 개발 환경**(Q8-A)이며 배포가 범위 밖이다
- NFR Requirements 단계가 SKIP 되었다 (성능 요구사항이 정의되지 않음)
- 복원력 확장이 비활성이다 (CQ7-B)

대신 이번 작업에서 **실제로 성능에 영향을 준 지점**만 측정하고 기록한다.

---

## 측정 대상: Community Dragon 페이로드 (R-6)

U1 이 도입한 외부 소스가 25MB 라, 캐싱이 없으면 요청마다 이를 받게 된다.
3단 캐시(BR-6)가 이를 막는지 확인한다.

### 측정 방법

```bash
cd backend && python -c "
import time
from app.services import static_data
static_data.reset_cache()
t=time.time(); n=len(static_data.champions()); print(f'1회차(콜드/디스크): {time.time()-t:.3f}s, {n}건')
t=time.time(); n=len(static_data.champions()); print(f'2회차(메모리):     {time.time()-t:.4f}s, {n}건')
"
```

### 실측 결과 (2026-08-04)

| 시나리오 | 지연 | 비고 |
|---|---|---|
| 콜드 (최초 페치) | 25MB 다운로드 시간 | 네트워크 속도에 종속. 1회성 |
| **디스크 캐시 히트** | **0.020초** | 서버 재시작 후 첫 요청 |
| 메모리 캐시 히트 | 즉시 | `lru_cache` 로 계산 자체가 1회 |
| 네트워크 실패 | 즉시 | 빈 목록 반환 |

**판정**: ✅ 통과. `uvicorn --reload` 로 잦은 재시작이 발생해도 재다운로드가 없다.

### 캐시 크기

| 항목 | 크기 |
|---|---|
| 원본 페이로드 | 25.1 MB |
| **디스크 캐시** (`data/cache/cdragon_set17.json`) | **2.1 MB** |
| 축소율 | 약 12배 |

> 설계 문서는 "수백 KB" 로 추정했으나 실제는 2.1MB 다.
> 아이템 배열이 세트별로 분리되지 않은 전역 3,680건이라 그대로 보관되기 때문이다.
> 더 줄이려면 Gateway 가 도메인 규칙(BR-2)을 알아야 해서 계층 분리가 깨진다.
> 읽기가 0.02초라 실사용에 문제가 없어 현 구조를 유지한다.

## 프론트엔드 번들 크기

| 항목 | 크기 | gzip |
|---|---|---|
| JS | 716.51 kB | 223.71 kB |
| CSS | 27.10 kB | 5.73 kB |

Recharts 도입으로 번들이 커졌고 Vite 가 500kB 초과 경고를 낸다.

**판정**: 로컬 개발 기준이므로 수용한다. 배포를 진행하게 되면 다음을 검토한다.

- `manualChunks` 로 Recharts 분리
- 차트를 쓰는 라우트만 `React.lazy` 로 동적 import

## Riot API 레이트리밋 (NFR-7)

**변경 없음.** `riot_live.py` 를 수정하지 않았으므로 기존 정책이 그대로 유지된다.

| 캐시 | TTL |
|---|---|
| 소환사 프로필 | 60초 |
| 리그 랭킹 | 300초 |
| 계정 이름 역조회 | 3600초 |

U4 의 차트는 이미 받아온 `matches` 배열을 클라이언트에서 집계할 뿐,
**추가 API 요청을 만들지 않는다.**

## 향후 부하 테스트가 필요해지는 시점

배포를 진행하게 되면 다음을 측정한다.

| 항목 | 측정 대상 |
|---|---|
| 콜드 스타트 | 컨테이너 재시작 시 25MB 페치 지연 → 이미지에 캐시 동봉 검토 |
| 동시 요청 | `_snapshot()` 의 락 경합 |
| Riot 프록시 | 개발용 키(2분당 100회) → 프로덕션 키 필수 |
