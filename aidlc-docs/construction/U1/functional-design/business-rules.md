# U1 Business Rules

필터 · 판정 · 변환 규칙. **모든 규칙은 Community Dragon 실데이터 관측에서 도출되었다.**

---

## BR-1. 챔피언 선별 (FQ2-A)

### BR-1.1 포함 조건
챔피언은 **아래를 모두** 만족할 때 도메인에 포함된다.

| # | 조건 | 근거 |
|---|---|---|
| 1 | 현재 세트(`TFT_SET`)의 `champions` 배열에 속한다 | 세트 경계 |
| 2 | **`traits` 가 비어 있지 않다** | 특성 없는 유닛은 PVE 몬스터·소환수 |
| 3 | `cost` 가 1~5 범위 | PVE 유닛은 `cost: 0` |
| 4 | `name` 이 존재하고 비어 있지 않다 | 미번역·내부 항목 배제 |

**관측 결과**: Set 17 전체 83개 → 조건 적용 후 **약 63개**

### BR-1.2 접두사 검사를 쓰지 않는 이유
기존 코드는 `id.startswith("TFT17_")` 로 판별했다. 이 방식은 두 가지 문제가 있다.

- **거짓 양성**: `TFT17_` 접두사를 가진 PVE 유닛·소환수 10개가 통과한다 (73 vs 63)
- **거짓 음성**: 접두사 규칙을 따르지 않는 이벤트 유닛을 놓친다

`traits` 유무는 **"플레이어가 배치할 수 있는가"** 라는 의미와 직접 대응하므로 더 정확하고, 세트가 바뀌어도 규칙 수정이 필요 없다.

### BR-1.3 정렬
`(cost 오름차순, name 오름차순)` — **기존 동작을 유지**한다.

## BR-2. 아이템 선별 (FQ1-A)

### BR-2.1 유효성 (모든 아이템 공통)
| # | 조건 |
|---|---|
| 1 | `name` 이 `null` 이 아니고 빈 문자열이 아니다 |
| 2 | `name` 이 `tft_item_name_` 으로 시작하지 않는다 (미번역 = 폐기/내부 항목) |

**관측**: 이 조건만으로 미번역·폐기 항목 14개가 제거된다.

### BR-2.2 조합 아이템 (`combined`)
| # | 조건 |
|---|---|
| 1 | BR-2.1 통과 |
| 2 | `composition` 배열이 비어 있지 않다 |
| 3 | `apiName` 이 `TFT_Item_` **또는** `TFT{SET}_` 로 시작한다 |

**관측**: 클래식 `TFT_Item_` **49개** + 현재 세트 `TFT17_` **16개** = **65개**

> 조건 3 이 없으면 구세트(TFT5·TFT6·TFT7…) 조합 아이템까지 295개가 포함되어,
> 현재 플레이와 무관한 항목이 목록의 대부분을 차지한다.

### BR-2.3 기본 재료 (`component`)
| # | 조건 |
|---|---|
| 1 | BR-2.1 통과 |
| 2 | **BR-2.2 로 선별된 조합 아이템들의 `composition` 에 등장한다** |

**관측**: 정확히 **10개** — B.F. 대검 · 굽은 활 · 쓸데없이 큰 지팡이 · 여신의 눈물 · 사슬 조끼 ·
음전자 망토 · 거인의 허리띠 · 쇠약의 장갑 · 스파툴라 · 프라이팬.
**TFT 표준 재료 10종과 정확히 일치한다.**

> **이 규칙의 장점**: "기본 재료 목록"을 하드코딩하지 않는다.
> 조합 관계에서 역산하므로 세트가 바뀌어 새 재료가 추가되어도 자동으로 따라간다.

### BR-2.4 참조 무결성
조합 아이템의 `recipe` 원소는 **반드시** 최종 아이템 목록에 `component` 로 존재해야 한다.

**검증 결과**: BR-2.2 로 선별한 65개 전부가 조건을 만족한다 (**누락 0건**).
BR-2.3 이 조합 아이템에서 역산하는 방식이므로 무결성이 **구조적으로 보장**된다.

**위반 시 처리**: 재료가 없는 조합 아이템은 목록에서 **제외**한다.
프론트 `ItemsPage` 의 조합법 Modal 이 `items.find()` 로 재료를 찾으므로, 없으면 깨진 Skeleton 이 노출된다.

### BR-2.5 내부 트리거 배제
`GrantOrbs*`, `GrantCompletedAnvil`, `GrantOrnnAnvil` 등 **110개**는 게임 내부 보상 트리거이며 아이템이 아니다.

BR-2.2·BR-2.3 은 `composition` 관계를 기준으로 하므로 **이들을 자동으로 배제한다.**

> ⚠️ **기존 코드의 결함**: `"_Item_" in id` 문자열 검사는 이 110개를 **아이템으로 포함**시킨다.
> `composition` 기반 판별로 교체하는 핵심 이유다.

### BR-2.6 최종 집계 및 정렬
| 분류 | 개수 |
|---|---|
| `combined` | 65 |
| `component` | 10 |
| **총계** | **75** |

정렬: `name` 오름차순 — **기존 동작 유지**.

## BR-3. 필드 변환

### BR-3.1 챔피언
| 도메인 | CDragon | 변환 |
|---|---|---|
| `id` | `apiName` | 그대로 |
| `name` | `name` | 그대로 (이미 한글) |
| `cost` | `cost` | 정수 변환 |
| `traits` | `traits[]` | **그대로** — 이미 한글 문자열 배열 |
| `iconUrl` | **`tileIcon`** | BR-4 변환 |

> ⚠️ **`squareIcon` 을 쓰지 않는다.** 이름과 달리 스플래시 아트를 가리킨다.
> 그리드 카드용 정사각 아이콘은 `tileIcon` 이다. (실측 확인)

### BR-3.2 아이템
| 도메인 | CDragon | 변환 |
|---|---|---|
| `id` | `apiName` | 그대로 |
| `name` | `name` | 그대로 |
| `type` | `composition` 유무 | 있으면 `combined`, 없으면 `component` |
| `recipe` | `composition[]` | `combined` 일 때만. `component` 는 `null` |
| `description` | `desc` | 없으면 `null` |
| `iconUrl` | `icon` | BR-4 변환 |

## BR-4. 에셋 URL 변환

```
입력:  ASSETS/Characters/TFT17_Briar/HUD/TFT17_Briar_Square.tex
출력:  https://raw.communitydragon.org/latest/game/assets/characters/tft17_briar/hud/tft17_briar_square.png
```

| # | 규칙 |
|---|---|
| 1 | 전체 경로를 **소문자**로 변환 |
| 2 | 확장자 `.tex` 또는 `.dds` 를 `.png` 로 치환 |
| 3 | 앞에 `https://raw.communitydragon.org/latest/game/` 결합 |
| 4 | 입력이 `null`·빈 문자열이면 `null` 반환 |

**검증 완료**: 챔피언 스플래시 · 챔피언 타일 · 특성 아이콘 · 아이템 아이콘 4개 패턴 전부 **HTTP 200**.

**실패 처리**: URL 이 유효하지 않아 이미지 로드가 실패해도 프론트 `IconImage` 가 이니셜 폴백을 표시한다.
백엔드는 URL 도달 가능성을 검증하지 않는다 (검증하면 요청마다 수백 번의 HTTP 호출이 발생한다).

## BR-6. 캐시 규칙 (FQ3-A)

### BR-6.1 조회 순서
```
① 메모리 캐시 → ② 디스크 캐시 → ③ 원격 페치
```

### BR-6.2 디스크 캐시 유효성
| # | 규칙 |
|---|---|
| 1 | 캐시 파일 경로: `data/cache/cdragon_set{SET}.json` |
| 2 | `fetchedAt` 이 **24시간** 이내면 유효 |
| 3 | 만료·손상·부재 시 원격 페치 |
| 4 | 페치 성공 시 디스크와 메모리 양쪽에 저장 |

**TTL 24시간 근거**: CDragon 은 게임 패치 주기(2주)로 갱신된다.
24시간이면 패치 반영이 충분히 빠르고, 개발 중 재시작마다 25MB 를 받는 일도 없다.

### BR-6.3 캐시 내용
전체 25MB 가 아니라 **현재 세트의 champions·traits + items 만** 추출해 저장한다 (수백 KB).

### BR-6.4 쓰기 실패
디스크 쓰기에 실패해도 **오류로 취급하지 않는다.** 메모리 캐시만으로 동작하며,
재시작 시 재페치가 발생할 뿐 기능은 정상이다.

## BR-7. 오류 처리

**원칙: 정적 데이터 조회는 절대 5xx 를 만들지 않는다.**

| 시나리오 | 처리 | 사용자 경험 |
|---|---|---|
| CDragon 네트워크 실패 | 빈 목록 반환 | 프론트 `EmptyState` |
| CDragon 응답이 JSON 이 아님 | 빈 목록 반환 | 동일 |
| `sets` 에 대상 세트 없음 | 빈 목록 반환 | 동일 |
| 캐시 파일 손상 | 무시하고 원격 페치 | 정상 (지연만 발생) |
| 캐시 디렉토리 생성 실패 | 메모리 캐시로만 동작 | 정상 |
| 개별 항목 변환 실패 | **해당 항목만** 건너뛴다 | 나머지는 정상 표시 |

**근거**: 기존 `dataset.py`·`static_data.py` 의 graceful degradation 패턴을 계승한다.
프론트는 이미 빈 배열을 정상 상태로 처리하도록 만들어져 있다.

---

## BR-8. 캐싱 무효화 판단 근거 기록

`static_data.py` 의 도메인 변환 결과는 `lru_cache` 로 프로세스 수명 동안 보관한다.

`dataset.py` 는 같은 패턴 때문에 CSV 갱신이 반영되지 않는 문제(TD-3)가 있으나,
**정적 게임 데이터는 세트 단위로만 변하므로** 프로세스 수명 내 불변 취급이 안전하다.

**이 판단 근거를 코드 주석에 남긴다** — 나중에 같은 함정으로 오해하지 않도록.
