## 2. 데이터 가용성 전제 (모든 요구사항의 기반)

이번 작업의 범위는 **어떤 API가 실데이터를 줄 수 있는가**에 의해 결정된다.

| API | 데이터 소스 | 이번 작업에서의 상태 | 근거 |
|---|---|---|---|
| `/api/summoner` | 라이브 Riot API | ✅ **실데이터** | Q4-A (유효한 키 보유) |
| `/api/leaderboard` | 라이브 Riot API | ✅ **실데이터** | Q4-A |
| `/api/champions` | DDragon 로컬 미러 | ✅ **실데이터** | Q6-A (미러 설치) |
| `/api/items` | DDragon 로컬 미러 | ✅ **실데이터** | Q6-A |
| `/api/statistics` | 전처리 CSV | ❌ **데이터 없음** | Q5-C (파이프라인 미실행) |
| `/api/comps` | 전처리 CSV | ❌ **데이터 없음** | Q5-C |

**핵심 결정 (CQ1-C)**: 데이터가 없는 두 화면은 목 데이터로 위장하지 않고,
**"데이터 수집 전"임을 명확히 알리는 의도된 안내 상태**로 처리한다.

이에 따라 완료 기준 Q8-A의 "모든 탭이 의미 있게 렌더된다"는 다음과 같이 해석한다:

> 모든 탭이 **깨지지 않고**, 데이터가 있으면 그 데이터를, 없으면 **왜 없고 어떻게 채우는지 알려주는 안내**를 보여준다.
> 빈 카드에 `-` 만 찍히거나 빈 목록이 침묵하는 현재 상태는 이 기준을 만족하지 않는다.

### FR-3. 백엔드 최소 수정 (F5 차단 요소 해소)

CQ2-A로 허용된 범위. **`backend/app/services/static_data.py`와 `backend/app/main.py`에 한정**한다.

| ID | 요구사항 | 근거 |
|---|---|---|
| FR-3.1 | `/api/champions`가 챔피언별 **특성(traits)을 채워서** 반환한다 (현재 항상 `[]`). **Community Dragon 기준 Set 17 챔피언 73개 중 63개가 특성 보유, 이름이 이미 한글이라 매핑 불필요** | CQ2-A, A-1 검증 |

## 4. Non-Functional Requirements

| ID | 요구사항 | 근거 |
|---|---|---|
| NFR-1 | **완료 기준**: `npm run dev`로 띄웠을 때 12개 라우트 전부가 깨짐 없이 렌더되고, §2의 해석 기준을 만족한다 | Q8-A |
| NFR-2 | **테스트**: 새로 만들거나 변경한 코드에 단위 테스트를 추가한다. 기존 코드 소급 테스트는 범위 밖 | CQ5-B |
| NFR-3 | **타입 안전성**: `npm run typecheck` 통과를 유지한다. `types/domain.ts`가 API 계약의 단일 원천이라는 원칙을 지킨다 | 기존 패턴 |
| NFR-4 | **기존 패턴 준수**: `QueryBoundary`(Loading/Error/Empty), React Query 훅, Tailwind 토큰 사용 규약을 따른다. 새 상태관리 라이브러리를 도입하지 않는다 | 기존 패턴 |
| NFR-5 | **반응형**: 데스크톱/태블릿/모바일 대응을 유지한다. 신규 차트도 반응형이어야 한다 | PRD §1.1 |
| NFR-6 | **회귀 방지**: 목 모드(`VITE_USE_MOCK=true`)로 되돌렸을 때도 모든 화면이 계속 동작해야 한다 | 기존 설계 자산 보존 |
| NFR-7 | **Riot 레이트리밋**: 백엔드의 기존 TTL 캐시 정책을 우회하거나 요청량을 늘리는 변경을 하지 않는다 | 개발용 키 제약 |

- **데이터가 없어 안내 상태로 처리할 것**: 데이터 통계, 전략가(조합) (2/6)
- **핵심 산출물**: 등수 분포 차트(전적검색), 챔피언·아이템 상세 실내용, 아이콘 연결, 개선된 빈 상태
- **백엔드는 `static_data.py`·`main.py`만** 최소 수정
- 보안·복원력·PBT 확장 전부 비활성, 테스트는 신규/변경분만
